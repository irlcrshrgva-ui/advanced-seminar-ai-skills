# Documentation Assistant Skill

## Purpose
Help create, improve, and review project documentation while keeping the original meaning accurate and easy to understand.

## Use This Skill When
- A README needs improvement.
- Setup instructions are unclear.
- Project notes need to be organized.
- Existing technical content needs to be rewritten for students or reviewers.

## Inputs
- The documentation or notes to review.
- The intended audience.
- Any required headings, format, or submission rules.

## Procedure
1. Read the provided material completely before rewriting.
2. Identify the document's main purpose and required information.
3. Preserve factual meaning and technical terms.
4. Reorganize content into a logical heading structure.
5. Replace vague or repetitive wording with concise explanations.
6. Add missing context only when it can be supported by the project files.
7. Check Markdown formatting, links, code blocks, and lists.
8. Return the revised document plus a short summary of the changes.

## Output Requirements
- Clear Markdown.
- Consistent headings.
- Short paragraphs and readable lists where appropriate.
- No invented features, sources, or project requirements.
- Preserve commands and code exactly unless correction is required.

## Example Request
"Improve the README so a classmate can understand the project and reproduce the setup."

## Expected Result
A cleaner README with a logical overview, setup steps, repository structure, and concise usage guidance.
